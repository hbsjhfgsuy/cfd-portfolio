# projects/

三个项目对应三条技术主线，不是九个并列算例。结构：

```text
projects/
├─ 01-basics/        基础算例集（4 个检查点，合成一个项目）
│  ├─ pipe-laminar/
│  ├─ backward-step/
│  ├─ flat-plate-yplus/
│  └─ fin-heat-sink/
├─ 02-flamed/        Sandia Flame D 湍流燃烧（核心项目）
└─ 03-burner/        燃气灶大气式燃烧器（场景项目）
```

每个算例目录内：

```text
├─ README.md    说明 + 对标结果（主体）
├─ setup.md     设置表
├─ data/        导出的 CSV
└─ figures/     图
```

提交规范见 [docs/how-to-add-a-case.md](../docs/how-to-add-a-case.md)。

## 判定标准（开工前写死，不达标就说明有问题）

| 项目 | 关键量 | 通过线 |
|------|--------|--------|
| 01a 圆管层流 | 出口速度剖面、压降 | < 1% |
| 01b 后台阶 | 再附着长度 x/H | ≤ 10% |
| 01c 平板边界层 | y+、Cf、对数律剖面 | 定性一致 + 网格无关 |
| 01d 翅片共轭传热 | 换热量、能量平衡 | < 10%，守恒 < 1% |
| 02 Flame D | 轴向温度峰值与位置 | < 15% |
| 03 燃气灶 | 趋势自洽、量级合理 | 定性 + 敏感性单调 |

## 一条纪律

**没有对标结果的算例不要提交。** 仓库里出现"跑通了但没对比"的目录，比空仓库更糟——
它证明你会点鼠标，但不会判断结果对不对。
